## [v0.21.0] - 2026-10-28

### Highlights

- Meetings by phone: omniagent meeting join attends a Zoom, Google Meet, or Microsoft Teams meeting by dialing in through Twilio or Telnyx, announces itself, prints a live transcript, and writes meeting notes with a summary, decisions, and action items
- The new meeting package attends any OmniMeet session, so the same attendant can serve other ways of joining a meeting

### Added

- meeting.Transcript, Segment, Summary, and ActionItem, with meeting.LLMSummarizer turning a transcript into a summary, decisions, and action items through any omnillm-core chat client ([`6bfb5c7`](https://github.com/plexusone/omniagent/commit/6bfb5c7))
- meeting.Attendant attends an OmniMeet attendee.Session: it announces the agent once the meeting admits it, streams the meeting audio to a streaming speech-to-text provider, collects the final transcript segments, leaves when its context ends, and summarizes ([`0b946c5`](https://github.com/plexusone/omniagent/commit/0b946c5))
- meeting.Record.Markdown renders meeting notes: details, the summary, and the timestamped transcript ([`962e4e6`](https://github.com/plexusone/omniagent/commit/962e4e6))
- voice.NewAudioGateway builds a Twilio or Telnyx gateway in audio mode that sends keypad digits on outbound calls ([`445ed8a`](https://github.com/plexusone/omniagent/commit/445ed8a))
- omniagent meeting join reads a meeting invitation (text or .ics, from a file or standard input), dials in, and writes the meeting notes to a Markdown file and optionally the full record as JSON; --ngrok opens a tunnel for the provider's webhooks ([`9583e03`](https://github.com/plexusone/omniagent/commit/9583e03))

### Changed

## [v0.20.0] - 2026-10-26

### Highlights

- AAuth for OpenAPI skills: the new aauthagent package enrolls omniagent at an agent provider and returns an HTTP client that signs every request as that agent, obtains person and auth tokens, and waits while the person approves, so an OpenAPI skill can call an AAuth-protected API with the agent's own identity
- examples/aauth-petstore: a terminal chat with the Petstore as an AAuth resource, with a container image; browsing needs only the agent's identity and orders ask the person to approve
- GET /readyz reports readiness (a real storage round-trip and an agent-configured check) apart from /health liveness, and the healthcheck subcommand is rebuilt on the same probe
- OpenAPI skills send array parameters and body fields as the spec describes, load a spec URL with the skill's own HTTP client, and refuse redirects and oversized spec documents
- Secrets: omnivault v0.6.0 redacts secrets when formatted or logged and its file provider refuses secret files other users can read; absolute file:// credentials keep working
- User guides live in docs/guides and design documents in docs/design: the getting-started guide and the architecture overview moved there

### Security

- omnivault v0.6.0: a Secret prints as [REDACTED] when formatted or logged, its file provider keeps secret paths inside its directory, and Secret.String is replaced by Reveal ([`2a40e1a`](https://github.com/plexusone/omniagent/commit/2a40e1a))

## [v0.19.0] - 2026-09-13

### Highlights

- OmniAgent deployed to production for the first time: Discord bot live on AWS Lightsail (us-west-2), image on both GHCR and Docker Hub, secrets sourced from SSM Parameter Store, runtime image converted to digest-pinned Chainguard static (no shell/package manager/libc)
- Fixed a logging self-deadlock that silently froze every CLI invocation before its first log line — the root cause of the first failed deployment attempt
- Full deployable config surface from the environment: OMNIAGENT_CONFIG_B64 for a complete config document, plus web UI and personal-auth env vars — no volume mount required
- Published container images are now multi-arch (linux/amd64 + linux/arm64) with SBOM, SLSA provenance attestations, and keyless cosign signatures
- Agent/skill marketplace primitives (portable listings, provider interface, static provider, registry adapters) for host applications
- LLM-based conversation summarization (WindowStrategySummarize) and durable session/cron storage wired into gateway run
